# RTX 4060 Scaling Law 搜索方案

本方案的目标是在约 3 小时 RTX 4060 GPU 时间内，用可解释的 IsoFLOPs
实验预测 12 小时最终训练应该采用的模型规模和数据量。3 小时允许约 30%
浮动，但实验按尽量接近 3 小时设计。正式提交前先运行短校准；所有 W&B
记录先写 offline，实验结束后统一同步。

## 1. 参数与计算量口径

Scaling Law 中的模型规模统一定义为精确的非 embedding 参数量：

```text
N = N_non_embedding
C = 6 * N_non_embedding * D
```

总参数量仍然记录，但只用于显存、checkpoint 大小和硬件吞吐分析。报告同时
给出课程建议的近似 `12 * n_layers * d_model**2`，用来说明精确计数与近似计数
的差异。所有拟合、分组和外推必须使用同一个 `N_non_embedding` 口径。

## 2. 固定因素

主网格只改变模型规模 `N` 和由 `D = C/(6N)` 得到的数据量。以下因素固定：

- DCLM 数据提交、tokenizer 提交、数据顺序和 data seed；
- context length 512；
- micro-batch 1、梯度累积 4、effective batch 4；
- AdamW、weight decay 0.01、warmup fraction 0.05、final LR fraction 0.1；
- gradient clipping 1.0、BF16、无 dropout；
- 4 次评估、每次使用同一份 65,536-token validation prefix；
- model seed 0；只有自适应复验阶段才改变 seed。

固定这些因素是为了让固定计算预算内的 loss 差异主要来自 `N` 与 `D` 的分配，
而不是学习率、batch、验证集或数据顺序变化。

## 3. 第一阶段：学习率与吞吐校准

用 `hidden=384, layers=8` 的代表性模型做逐级校准。第一轮训练 262,144
tokens；由于最优点连续落在搜索右边界，又扩展一次短搜索，并用 1,048,576
tokens 做最终稳定性比较：

| 训练 tokens | Peak LR | 最终 validation loss | 训练 runtime |
|---:|---:|---:|---:|
| 262,144 | 1e-4 | 44.8786 | 10.06 s |
| 262,144 | 3e-4 | 33.1945 | 10.00 s |
| 262,144 | 6e-4 | 31.2364 | 10.14 s |
| 262,144 | 1e-3 | 30.1517 | 10.02 s |
| 262,144 | 2e-3 | 26.9660 | 10.09 s |
| 262,144 | 3e-3 | 23.7829 | 10.05 s |
| 1,048,576 | 3e-3 | 8.5514 | 25.11 s |
| 1,048,576 | 6e-3 | 7.5597 | 25.08 s |
| 1,048,576 | 1e-2 | 7.1334 | 25.04 s |

这 3 个实验最多预留 15 分钟，不进入 Scaling Law 拟合。选择规则不是机械选择
最后一个 loss 最低的实验，而是先排除 NaN、发散、明显震荡或梯度异常的配置，
再比较完整 loss 轨迹和最终 validation loss。

所有轨迹均有限且持续下降，最终固定 peak LR 为 `1e-2`。长 pilot 的中位吞吐为
`3.5536e12` 非 embedding FLOPs/s。校准结束后，用实际结果计算：

```text
measured_flops_per_second = estimated_flops / runtime_seconds
```

主网格必须用该非 embedding FLOPs/s 重新生成 runtime 上限。如果 pilot 选择的
学习率不是 3e-4，主网格也必须使用新学习率重新生成，不能直接提交预览配置。

## 4. 第二阶段：4 × 4 IsoFLOPs 主网格

### 模型候选

| hidden | intermediate | layers | 精确非 embedding N | 12Ld² 近似 | 总参数 |
|---:|---:|---:|---:|---:|---:|
| 256 | 704 | 5 | 4,017,536 | 3,932,160 | 12,209,536 |
| 320 | 896 | 6 | 7,623,488 | 7,372,800 | 17,863,488 |
| 384 | 1,024 | 8 | 14,163,328 | 14,155,776 | 26,451,328 |
| 512 | 1,408 | 10 | 32,124,672 | 31,457,280 | 48,508,672 |

非 embedding 规模覆盖约 8 倍，并且大致按对数间隔排列。这样每个计算预算都有
机会观察到“模型太小、数据太多”和“模型太大、数据太少”两侧，从而包围内部最低点。

### 每个配置的数据量

`D` 被取整到训练 batch 和 4 次评估都能整除的边界。主网格使用固定 revision
和校验和的 200M-token DCLM manifest，不重复数据。各点的计算量取整误差低于
0.1%，足以把同一行视为固定计算预算。

| 目标 C | D @ N=4.02M | D @ N=7.62M | D @ N=14.16M | D @ N=32.12M |
|---:|---:|---:|---:|---:|
| 4.5e14 | 18,669,568 | 9,838,592 | 5,292,032 | 2,334,720 |
| 9.0e14 | 37,339,136 | 19,677,184 | 10,592,256 | 4,669,440 |
| 1.8e15 | 74,670,080 | 39,354,368 | 21,184,512 | 9,338,880 |
| 3.6e15 | 149,348,352 | 78,700,544 | 42,360,832 | 18,677,760 |

四个计算预算严格按 2 倍递增。相比只用三个预算，四个点更适合检查 power law
稳定性、做 leave-one-budget-out 敏感性分析，并拟合最终 loss 随 compute 的变化。

### 运行顺序和时间控制

提交顺序为计算预算从小到大，然后模型规模从小到大。因此前 4 个实验会先形成
一条完整的低计算量 IsoFLOPs 曲线，同时测出四种模型在 4060 上的实际吞吐。

最终主计划使用长 pilot 实测的 `3.5536e12` 非 embedding FLOPs/s：

- 预估纯训练总时间：2.11 小时；
- 保守 runtime 预留：2.89 小时；
- 每档初始 runtime 上限：300、329、658、1,317 秒。

首条 profile 测得四种模型的吞吐约为 2.58、3.39、4.22、5.53 TFLOPs/s，
说明 runtime 明显依赖模型规模。尚未启动的两个高预算 4.02M 模型因此改用
802 和 1,603 秒上限；900T 小模型使用已保存 checkpoint 续跑。低预算最优点
位于左边界，因此额外安排 `hidden=192, layers=4, N=1,771,712` 的补点。

## 5. 第三阶段：自适应补点或复验

主网格完成后只用实际剩余时间做以下操作，优先级从高到低：

1. 某条 loss–log(N) 曲线的最低点位于最小或最大模型边界：向边界外增加模型；
2. 同一预算下两个最低 loss 很接近：用新 model seed 复验这两个候选；
3. 曲线已有清晰内部最低点：复验中、高计算预算的最低点；
4. 达到约 3 小时则停止；只有关键曲线仍缺少边界或复验时才使用最多 30% 浮动。

不能在最低点位于边界时直接报告该点为 `N_opt`，因为这只能说明最优规模还在
搜索区间外。

## 6. 拟合方法和质量检查

对每个固定计算预算，先画所有观测点，再在 `log(N)` 空间拟合局部二次曲线：

```text
L_C(log N) = a * (log N)^2 + b * log N + c
```

只有 `a > 0` 且顶点落在已测试模型范围内时，才使用顶点作为连续的 `N_opt(C)`。
同时保留实际最低观测点；如果二次顶点与观测最低点偏差过大，报告会优先采用观测点
并标记拟合不稳定。

随后在 log-log 空间拟合：

```text
N_opt(C) = A * C**alpha
D_opt(C) = B * C**beta
```

检查项目包括：

- 每条 IsoFLOPs 二次曲线是否有内部最低点；
- power-law 的 R²、残差和指数置信区间；
- `alpha + beta` 是否接近 1；
- 去掉任意一个 compute budget 后外推结果变化多大；
- 重复 seed 的 loss 波动是否会改变最优模型选择；
- 目标 12 小时点相对观测区间的外推倍数。

最优 loss 随 compute 的关系另外拟合为带不可约项的形式：

```text
L_opt(C) = L_inf + K * C**(-gamma)
```

只有四个计算预算时该 loss 外推仍然不确定，因此最终必须给区间和敏感性结果，不能只
给一个看似精确的小数。

## 7. 12 小时最终模型

4060 的 12 小时目标不能直接照搬 B200 FLOPs。首先从主网格拟合不同模型规模的
tokens/s 或非 embedding FLOPs/s，再联合求解：

```text
N = N_opt(C)
D = D_opt(C)
estimated_runtime(N, D) <= 12 hours
```

输出应包含推荐架构、精确非 embedding 参数、总参数、训练 token、理论 FLOPs、
预计 wall time、预计 validation loss 和不确定区间。当前 200M calibration 数据仍可能
不足以支持最终 `D`；最终数据量确定后再通过 `proxy_on` 准备更大的固定 DCLM manifest。

## 8. 最终图像和课程问题映射

至少生成以下图像：

1. 四张/一组固定 C 的 validation loss–model size IsoFLOPs 曲线；
2. `N_opt(C)` 的 log-log 数据点、拟合线和 12 小时外推点；
3. `D_opt(C)` 的 log-log 数据点、拟合线和 12 小时外推点；
4. `L_opt(C)` 数据、拟合和预测区间；
5. 模型规模与 tokens/s、非 embedding FLOPs/s、显存、wall time 的硬件图；
6. 重复 seed 或 leave-one-budget-out 的稳定性图/误差条。

这些结果分别用于回答课程要求的固定因素、为什么采用 IsoFLOPs、实际拟合方法、
拟合质量、给定最终预算的最优模型规模、预测 validation loss，以及如果接近多个模型
规模时最终如何做离散架构选择。
